# hbench: Zed's agent and the same-model comparison, 2026-10-10 / 2026-11-05

Filip asked: if Hermes and he use the same prompt and the same model, in Zed or in another tool, do they get
similar results? These cells answer it on the 7 tasks of the first run (see RESULTS-2026-10-09.md).

Where: Zed cells on 2026-11-05 on the lab dev VM `hermes-dev-1` (lab-w01), Claude Code + deepseek-v4.1-flash on
2026-10-10 on the dev VM `hermes-dev`; same Docker image recipe, Hermes repos mounted read-only, Ollama Cloud.
Zed = Zed's own agent loop via `eval-cli` (release `zed-eval-cli-f16f965-p1`), with its `terminal` tool off:
it never returns in headless runs on the VMs (same default as Hermes' `agent-run`, WOBI #86), so Zed edits
and the harness runs the hidden tests. 1 attempt per cell, 0 harness errors, 0 timeouts.

All five rows fail only `hermes-tool-name-xml-leak` (only Opus solved it; see the first-run notes) and solve
the other six tasks.

## What it says

* **Same model, same tasks solved.** With deepseek-v4.1-flash and with glm-5.3, Claude Code, Copilot CLI and
  Zed's agent solved exactly the same tasks. On these bugfixes the model decides *whether* a fix is found.
* **The framework decides how fast and how much it costs.** Zed took ~2× (deepseek-v4.1-flash) to ~5×
  (glm-5.3) Claude Code's time, with more tool calls and up to 6× the output tokens. Copilot sat in between.
  So: same prompt + same model gives the same answer here, not the same effort.
* **For Filip's own Zed (deepseek-v4.1-flash):** Hermes running Zed's agent on that model behaves like his
  editor's agent on these tasks (6/7, about a minute each). Claude Code on the same model is the faster
  harness for Hermes' headless work.
* Caveats: one attempt per cell, an easy task set (5 of 7 solved by every cell), and Zed without its terminal
  (it can't run tests itself, which may cost it on harder tasks).
