## What it says (one attempt per cell, so treat as a first signal)

* **Every model handles these fixes.** 5 of 7 tasks were solved by all 8 combinations, including the
  "hard" hermes-agent worktree fix. The set is too easy to rank models; it needs harder tasks and 3+
  repeats.
* **Only Opus generalised.** hermes-tool-name-xml-leak's hidden tests also cover `<`, `'` and
  leading-quote variants that the instruction doesn't show. Only Opus handled them. Kept as is, as a
  generalisation test.
* **Claude models are the most efficient.** Opus and Sonnet were fastest, with the fewest tokens and
  5–10 tool calls per task; Ollama Cloud models needed 2–3× the tool calls.
* **Cheap model ≈ big model here.** glm-5.3-flash matched glm-5.3 at the same speed. deepseek-v4-pro
  (Hermes' current default) and kimi-k2.7-code were the slowest.
* **Framework matters for speed, not (yet) success.** Copilot CLI with glm-5.3 solved the same tasks as
  Claude Code with glm-5.3 but took ~3× longer (median 141s vs 49s, up to 6.6 min) with 2–3× the tool
  calls.
